# dsh-work-summary · 日报 / 周报 / 月报

把「定时写工作日报」扩展成日报、周报、月报三条流水线：采集、校验、写盘、推看板由工具确定性地完成，模型只负责写正文。

运行期数据都放在 `~/.dsh/dsh-work-summary`（Windows：`%USERPROFILE%\.dsh\dsh-work-summary`）：日报、周报/月报、看板、`_主线.md`、`_工作区.md`、`_源数据`、`_归档`、`_日志`、`settings.json`。首次激活时自动创建，目录可在设置页改；代码与提示词随插件仓库走。

## 它提供什么

| 工具 | 作用 |
|---|---|
| `daily_report_collect` | 运行 `collect-day.ps1` 采集当天痕迹（先自动发现近两天活跃的工作区），返回源数据路径、小节清单、看板未完成条数、工作区列表，以及六节日报模板；超过 60 个源数据时自动按季度归档 |
| `daily_report_save` | 校验六个固定小节（一、今日概览 … 六、明日开场清单），写 `日报-YYYY-MM-DD.md`，按 `#### M-…` 小节维护 `_主线.md` 账本，再把「明日开场清单」推进看板；返回质量软校验 `warnings` 与主线列表 |
| `work_summary_period` | 跑 `collect-range.ps1` 采集区间底稿，按区间日报 + 看板拼四节周报/月报，同款校验后落盘并推看板；`offset: 1` 取上一周期 |
| `daily_report_board` | `show` 列未完成待办；`done` 移到「已完成」；`drop` 移到「已放弃」；`update` 改优先级 / 截止日 / 状态 |

`daily_report_save` 缺小节、只写了骨架、或留有 `TODO / 待填 / {{…}}` 时会直接报错且**不写文件**，按报错补齐后重调即可；同一日期重复提交会整篇覆盖。正文里的 `#### M-YYYY-MM-DD-NN` 主线小节会同时维护 `_主线.md`，引用账本外的旧 ID、新 ID 缺小节或状态非法同样报错且不写任何文件。采集写 `_源数据`，超过 60 个时自动把旧文件归档到 `_归档`。

## 质量自检（软校验）

质量检查在结构硬校验之后、写盘之前执行，**只返回提醒，不改变落盘结果**。`daily_report_save` 的结果多一个 `warnings` 数组，`text` 里也会列出同样内容：

- **证据密度**：统计正文中的路径（Windows 盘符、UNC、POSIX/相对路径、带扩展名文件名）与 7–40 位十六进制提交号，去重后少于 `quality.minEvidence`（默认 3）就提醒。
- **空话词**：命中「继续推进 / 加强沟通 / 持续优化 / 进一步提升 / 稳步推进 / 深入推进 / 扎实做好 / 高度重视 / 协同发力 / 形成闭环 / 提质增效 / 落地见效」时列出命中词，提醒换成具体动作、对象或结果。
- **建议可执行性**：`## 五、后续建议` 里既没有路径，也没有命令（`npm test`、`pwsh …`、`Get-…` 等）时提醒补具体文件或命令。

`quality.minEvidence` 可以写成嵌套对象，也兼容扁平的 `quality.minEvidence` 键；非正整数退回默认 3。`warnings` 为空表示没发现问题，日报照常写入并推看板。

## 源数据归档

每次 `collect-day.ps1` 结束时会数一遍 `_源数据/*.md`。超过 60 个时，按文件名里的数据日期排序，把最旧的超出部分按季度打进 `_归档/YYYY-QN.zip`：

- 只处理不是当天的文件；当天文件永远留在 `_源数据`。
- 打包后先读 zip 条目，确认这些文件都在，再删除原文件；失败只写一行「归档失败」，采集照常以退出码 0 结束。
- 同一季度包已存在时用 `-Update` 追加，并在 `_归档/索引.md` 追加一行（归档时间、季度、新增数、区间、包名）。
- 归档结果同时写进当天源数据的「6. 源数据归档」和运行日志；没触发归档时两处都不写。

## 工作区自动发现

`collect-day.ps1` 不依赖单个固定根：每次采集先扫窗口内（`-Date` 当天与前一天，共两个日历日）的 DSH 会话文件 `session.v4.jsonl.zstd`，把每条 `session` 记录的 `cwd` 当成候选工作区：

- 同一路径去重，junction / symlink 解析到真实路径后归并；默认只精确跳过 `HOME` 本身（家目录下的项目仍可发现），并跳过 `HOME\AppData`、`~/.dsh`、数据目录、TEMP、Windows / Program Files / ProgramData 与盘符根，避免把系统目录当工作区。
- 上限 12 个工作区、每区 400 个改动文件、12 个 Git 仓库；单个工作区最多遍历 20000 个目录，到顶就在源数据里注明「目录数超过上限，已停止遍历」。超出的截断并注明，不静默丢。
- 父子工作区同时出现时，子区从父区扫描中剪掉，文件数不重复统计。
- `settings.json` 的 `workspace` 是可选的额外固定根，留空就只按会话发现；给了就一直扫，即使当天没有会话。显式根也拒绝盘符根（`F:\` 这类整盘扫描没有意义）。
- `_工作区.md` 在数据目录首次采集时自动生成：`## 别名` 支持 `- F:\history_novel = 小说`，`## 忽略` 支持 `- D:\scratch`；显式配置的根不受忽略影响。别名只影响显示名，路径仍是真实路径。`<!-- ... -->` 注释块里的示例不生效。
- 找不到 zstd 或有会话解压失败时，源数据第 0 节会写明警告；不会静默当成「没有工作区」。
- 一个工作区都没发现（没有会话、没有显式根）时，退回数据目录本身，并在源数据里写「未从会话发现工作区，退回指定根。」，不会产出空表。

源数据第 0 节「工作区（近两天活跃）」是一张表：

| 工作区 | 路径 | 近两天会话 | 近两天工具调用 | 当日改动文件 |

第 1 / 2 / 5 节都按 `### 名字（`路径`）` 分块，改动文件、Git 提交与产物目录各归各的工作区。`daily_report_collect` 解析这张表，把 `workspaces`（`name` / `path` / `sessions` / `tools` / `files`）随结果返回；设置页的「工作区」块只读展示最近一次采集发现的工作区。

## 主线账本与日报结构

「主线」是一次完整的交付，可以跨天、跨工作区。日报正文用 `#### M-YYYY-MM-DD-NN 标题` 标记主线，小节内固定三行：

- `- 工作区：绝对路径`（跨多个工作区用逗号分隔）
- `- 状态：进行中 / 完成 / 受阻 / 放弃`（四值精确匹配；「未完成」这类否定式会被拒绝）
- `- 判据：可验收的结果`

`daily_report_save` 是账本的唯一写方：

- 写入前读 `<reportDir>\_主线.md`，校验正文引用的每个 M-ID：日期晚于日报日期、日期不是当天且不在账本里、当天新 ID 没有 `####` 小节、缺少 `- 状态：` 行、状态不在四种之内、ID 序号不是两位，都会报错，日报与账本都不写。
- 校验通过后合并：新 ID 追加；旧 ID 只在日报日期不早于「最近产出」时更新状态与判据，标题 / 工作区 / 看板始终补全，首次产出取较早日期、最近产出取较晚日期——补写旧日报只补证据，不会把已完成回拨成进行中。账本里的 `- 备注：` 会原样保留。
- 账本日期缺失或写成 `—` 时按空处理，周期报告照常生成，区间显示 `— → —`。
- `mainline.stallDays`（默认 3）：未完成且未放弃、最近产出距今 ≥ 阈值的主线在返回值里显示「受阻」；如果「四、问题与风险」没有提到它，追加一条软提醒。
- 采集脚本第 7 节「未清主线」读同一份账本，按 `-Date` 算挂起天数，源数据里就能看到哪些交付停住了。

日报结构：一、今日概览是一张 2–4 行的主线总览表（主线 / 工作区 / 今日产出 / 状态 / 下一步）；二、做了什么按 `### 工作区名（路径）` 分块，块内每条主线一个 `####` 小节；三、结果与产出表增加「主线」列；四、问题与风险、五、后续建议、六、明日开场清单都标 M-ID。六个小节名不变，既有校验与周期聚合不用改。

## 周报 / 月报聚合

`work_summary_period { from?, to?, kind?, offset?, content?, push? }` 把「一段区间」当成一份更大的日报来做：

- 区间：`from` / `to` 成对；都不传时 `week` 取本周一至今天、`month` 取本月 1 号至今天。`kind` 可省，整月判 `month`、跨度 7 天判 `week`、其余 `custom`；最长 400 天。定时任务用 `offset: 1` 取上一个周期（上一周 / 上一月），`offset` 取 0–60，且不能与 `from` / `to` 同时给。
- 采集：`scripts/collect-range.ps1` 写 `_源数据/周期-<from>_<to>.md`，含区间概况、日报覆盖、每日概览、产出汇总、问题与风险、开场清单、看板现状、Git 提交、工作区改动、源数据覆盖、复发候选，以及第 12 节「主线（区间）」——合并日报 `#### M-...` 小节与 `_主线.md` 账本，按工作区分组列出首次 → 最近产出、状态、判据 x/y 与挂起天数；账本里未清、本期日报没写小节的标「本期未推进」；主线 ID 自带的日期晚于区间结束时不会出现（补写历史周期时不倒灌）。
- 正文：四节固定（首节 `本周/本月/本期主线`，末节 `下周/下月/下期开场`，中间「关键产出」「未清与复发」）。不传 `content` 时从区间日报 + `_主线.md` + 看板自动拼草稿；首节按工作区分组，每条主线写成 `M-ID 标题：起点 → 终点（状态，判据 x/y，挂起 N 天）`，跨期未动的标「本期未推进」。传了 `content` 就走同一套缺节 / 空骨架 / 占位符校验。
- 落盘：周报 `周报-<from>_<to>.md`；整月 `月报-YYYY-MM.md`，非整月 `月报-<from>_<to>.md`；自定义 `周期-<from>_<to>.md`。
- 看板：只推最后一节，`push-to-board.ps1 -Section <末节名>`，按标题 / 条目指纹去重，同一区间连跑第二次新增 0 条。

## 计划任务

`scheduleEnabled` 打开时（默认打开），插件在激活后确保存在三条托管任务。日报按标题（精确或前缀）识别，周报 / 月报按各自标题识别；日报还会用提示词认领引用 `collect-day.ps1` 的旧任务，避免互相认领：

- **日报**：标题 `scheduleTitle`（默认 `每日工作日报`），时间 `scheduleTime`（默认 23:00）。
- **周报**：标题 `weekScheduleTitle`（默认 `每周工作周报`），每周一 `weekScheduleTime`（默认 01:00），生成上一周（周一至周日）。
- **月报**：标题 `monthScheduleTitle`（默认 `每月工作月报`），每月 1 号 `monthScheduleTime`（默认 01:00），生成上一个自然月。

已有任务时：同步提示词到当前版本；周报 / 月报还会把任务的时间与启停对齐 `settings.json` 里保存的值（小时或分钟不同才改 rrule）。都没有时：

- 日报：`scheduleAdopt` 打开则先认领提示词里引用 `collect-day.ps1` 的旧任务，改写提示词但**保留原来的时间与投递会话**；否则新建一条，投递到可复用的新会话（`new_once`）。
- 周报 / 月报：对应 `weekScheduleEnabled` / `monthScheduleEnabled` 为 `true`（默认）才新建，`false` 就不建。

设置页改周报 / 月报的时间或启停时，先写 `settings.json` 再 `schedule.edit`；任务被删掉后，下次重启会按保存的值重建。日报时间仍然只改任务自己的 rrule。

计划任务只是把流程讲一遍，正文规则仍以 `promptPath`（默认插件目录下的 `PROMPT.md`）为准，改规则不用改插件代码。周期任务的提示词要求调用 `work_summary_period` 并传 `{"kind":"week","offset":1}`（月报同理），由工具自己算上一周期。

新建的周报 / 月报任务从下一个触发点开始，不会补跑刚过去的周期；要补当期报告，直接手动调一次 `work_summary_period`。

## 侧边栏页面

插件带一个浏览器半（`client.js`，由 `package.json` 的 `dsh.client` 声明）：在左侧栏注册「日报」入口，点击后在主区打开同名页面，不必切换会话。

- 面板默认停在「看板」，页签顺序是「看板 / 日报 / 周期 / 统计 / 设置」。日报列表按日期倒序，点一天看正文；日报页顶部还有「主线」面板，只读 `_主线.md` 账本：列出未清主线（受阻排前面）、工作区末级目录、状态、最近产出与挂起天数，账本为空时提示怎么生成。「周期」标签单列周报/月报，点一份看整篇；「统计」按天展示最近 13 周的产出强度，下面再列 30 天产出趋势和看板交付结构，点热力图格子跳到当天日报；标题、列表、引用做了轻量排版，Markdown 表格（表头 + `|---|` 分隔行 + 数据行，首尾竖线可省略）会合成真正的表格（`thead` / `tbody`，按 `:---` / `---:` / `:---:` 左 / 右 / 居中，列数以分隔行为准裁剪补空），其余按纯文本渲染。
- 看板按「待办 / 进行中 / 已完成 / 已放弃」分节展示；待办与进行中再按「已过期 → P1 → P2 → P3 → 未标注」分组，组内按截止日升序、无截止日排最后，同截止日再按日期倒序。每行显示日期、来源、`#h` 指纹与详情，右侧可直接改优先级、截止日、状态，改完立即写回；待办 / 进行中还带「开工」，在当前工作区新建会话并把这条待办发过去。
- 「设置」标签可以改日报文件目录、额外工作区根、日报 / 周报 / 月报的触发时间、临时暂停或恢复投递、改运行日志目录：读写走 `GET|POST /dsh-work-summary/schedule`，POST body 为 `{"reportDir":"D:\\reports"}`、`{"time":"HH:MM"}`、`{"active":true|false}`、`{"weekTime":"HH:MM"}`、`{"weekActive":true|false}`、`{"monthTime":"HH:MM"}`、`{"monthActive":true|false}`、`{"workspace":"D:\\projects"}` 或 `{"logDir":"D:\\logs"}`（logDir 空串表示回落到默认目录）。工作区不用登记，采集时从近两天有活动的 DSH 会话自动发现；输入框只是额外固定的根，留空表示只自动发现，页面下方只读列出最近一次采集发现的工作区。
- 日报时间以那条任务的 rrule 为唯一真源：设置页直接 `schedule.edit` 改 `timing`，不写 YAML，也不另存配置，所以重启后不会被 `scheduleTime` 默认值盖回去（它只在需要新建任务时用一次）。周报 / 月报的时间与启停额外落到 `settings.json`，重启时再对齐任务，任务被删也能重建。
- 页面数据由 Host 的路由提供：`GET /dsh-work-summary/state`（看板全文 + 最近 91 份日报正文 + 最近 40 份周报/月报 + `mainlines` 主线视图，`cache-control: no-store`）、`POST /dsh-work-summary/board`（看板写回）与上面那条设置路由。每份日报额外带 `lines`（非空行数）、`outputs`（第三节「结果与产出」里的表格行或列表项数）和 `score = lines + outputs * 3`，顶层带 `today`（按 `scheduleTimeZone` 算的当天）。
- 日报与周期正文仍然只读；看板页的写入口只改条目元数据 / 状态，不动正文。命令行等价操作是 `push-to-board.ps1 -Done/-Drop/-Update`。「开工」只新建会话并发送任务，不修改看板文件。

## 看板写回

条目格式是 `- [ ] 日期 ｜ 标题 ｜ 来源：… ｜ #h指纹 ｜ @P1 ｜ !2026-11-30`，优先级与截止日两段可省略，老看板不需要迁移。`@P1` / `@P2` / `@P3` 表示优先级，`!YYYY-MM-DD` 表示截止日；`none` 用于清空。

- 页面每行一次只提交一个字段：`POST /dsh-work-summary/board`，body 形如 `{"keyword":"#h12345678","priority":"P1"}`、`{"keyword":"标题片段","due":"2026-11-30"}` 或 `{"keyword":"…","status":"doing"}`。
- `keyword` 优先用条目的 `#h` 指纹，避免标题重复；也可以用标题子串，但匹配到多条会直接报错，要求写得更具体。
- `status` 取 `todo` / `doing` / `done` / `drop`，分别对应四个小节；跨节移动会保留「详情」行，标记完成 / 放弃时补当天日期。只改优先级或截止日时保留原来的完成 / 放弃日期。
- 同一条目重复提交同一个值是幂等的；脚本按单条匹配后重写，不会追加副本。失败返回 400 与中文原因，页面在顶部显示，不改本地缓存。

## 看板一键开工

待办 / 进行中条目的右侧有「开工」：在当前工作区新建一个会话，把这条待办作为首条用户消息发出去，直接进入处理，不需要复制标题或手动粘贴。

- 工作区取当前会话所属的那个；取不到归属时退回工作区列表第一项。一个工作区都没有时直接报「还没有工作区」。
- 新建会话用客户端 `sessions.create({ workspaceId })`；随后用 `sessions.using(sessionId, { source: 'controllerOperation' }, …)` 拿到 `binding.session` 发首条消息，确认被接受后再 `uiWorkspace.openSession(sessionId)` 切过去。这样发送失败时页面还留在看板，能直接看到原因。
- 首条消息包含「看板待办：标题」、登记日期、优先级、截止日、详情、来源和 `#h` 指纹，末尾要求先简短说明计划、直接开始处理，完成后把待办标成已完成。
- 发送走 `session.prompt([{ type: 'text', text }], 'queue')`；它失败时不抛异常，页面检查 `result.ok === false` 并把 `result.error.message` 显示出来。创建期间按钮显示「建会话…」并禁用。
- 这是纯客户端能力，不改 Host 路由和看板文件；页面刷新后生效。没有 `sessions.create` / `sessions.using` 的旧版 DSH 会提示升级。

## 贡献热力图

「统计」页签上半部分把最近 13 周（周一起始，最多 91 天，未来格禁用）排成 7 行 × 13 列的日历格，格子随窗口在 18–44px 之间伸缩，颜色只表示当天日报的 `score`：

- 强度按窗口内**有日报**样本的 25 / 50 / 75 分位动态切 4 档，没有固定阈值；样本少于 4 天时上档会自然空着，不会硬凑。
- 未到日期画成禁用格；有日期但无日报画虚框，点击提示「该日无日报（日期）」；有日报点击切到「日报」页签并定位到该日。
- 格子 `title` / `aria-label` 写明「日期 · N 行 · N 条产出 · 强度 N」，图例注明「行数 + 产出条数 × 3」的口径，颜色不是阅读正文的替代品。
- 数据只来自 `/state`，渲染是纯前端映射；91 格的节点量级不需要额外请求或缓存。

## 统计页

「统计」页签 = 热力图 + 两张卡片，全部由 `/state` 直接算，不新增请求，也不引入图表库。

- **产出趋势**：最近 30 个自然日，按每份日报的 `outputs` 画柱；缺日报的日期补 0，空档不会被“连平”。折线是含当天的 7 日移动平均，首日窗口不足 7 天时按已有天数平均。纵轴取窗口最大值向上取偶数，至少为 2；柱的 tooltip 同时给出当天行数。
- **看板交付结构**：按「待办 / 进行中 / 已完成 / 已放弃」四个小节计数，堆叠条宽度为各状态占比；完成率 = 已完成 / 总数，放弃率 = 已放弃 / 总数，未关闭 = 待办 + 进行中。空看板只显示空态，不画 0 宽度条。
- `buildTrend(state, days = 30)` 与 `boardStats(state)` 是纯函数，`test/stats.test.mjs` 覆盖补零、7 日均值、计数与空看板。

| `pwsh` | `pwsh` | PowerShell 可执行文件 |
| `timeoutMs` | `240000` | 单个脚本超时 |
| `pushOnSave` | `true` | `daily_report_save` 默认是否推看板 |
| `quality.minEvidence` | `3` | 日报软校验要求的最少路径/提交号引用数；嵌套或扁平点号键都可 |

| `scheduleEnabled` | `true` | 是否托管计划任务 |
| `scheduleAdopt` | `true` | 是否认领旧日报任务 |

| `logDir` | `<reportDir>\_日志` | 运行日志目录；设置页改它，留空用默认 |

## 运行日志

每次调用脚本都往 `logDir` 里追加一行，文件按天切：`dsh-work-summary-YYYY-MM-DD.log`。

```
2026-11-23 14:31:42 [info] push-to-board.ps1 -Report ~\.dsh\dsh-work-summary\日报-2026-11-23.md -BoardPath ~\.dsh\dsh-work-summary\看板.md → exit 0，812ms
```

- 记的是：脚本名、参数、退出码、耗时；失败时再带 stderr 尾部（截 800 字符）。
- 计划任务同步/认领/创建、设置页改目录或周报 / 月报时间也会落一行。
- 日志目录不可写不会影响日报本身（写失败直接跳过）。
- 设置页的「日志 · 目录」改的就是它，空值表示回落到 `<reportDir>\_日志`；设置（日报目录 + 额外工作区根 + 日志目录 + 周报 / 月报的时间与启停）存在 `~/.dsh/dsh-work-summary\settings.json`。

## 使用示例

```
帮我补一下 2026-11-18 的日报
→ daily_report_collect { date: "2026-11-18" }
→ 读 sourcePath，写正文
→ daily_report_save { date: "2026-11-18", content: "…" }
```

日常只需说「写今天的日报」，模型会依次调用 collect → save。

```
帮我写上周的周报
→ work_summary_period { from: "2026-11-18", to: "2026-11-24", kind: "week" }
→ 工具跑 collect-range.ps1、拼四节草稿、写 周报-2026-11-18_2026-11-24.md、推看板
→ 回复里给：文件路径 + 本周主线 3 条以内
```

也支持 `{ "kind": "month" }` 不传日期（本月 1 号至今天）、`{ "kind": "week", "offset": 1 }` 取上一周，或传 `content` 自己写四节正文。

## 限制

- 代码（`scripts\` 与 `PROMPT.md`）随插件仓库走，`reportDir` 只放运行期数据；插件不改写它们，只调用。
- 采集脚本依赖 `zstd.exe` 解析会话，缺失时该段自动降级为空。
- 调用脚本走 `pwsh -Command`，命令开头固定把 `[Console]::OutputEncoding` 与 `$OutputEncoding` 设为 UTF-8。管道重定向下 pwsh 默认按系统 ANSI（936）写 stdout，Node 按 utf8 解码就会得到乱码，`已写入 N 条` 这类中文输出将解析失败；改动这行前请先跑一次 `daily_report_board show` 确认中文正常。
- 计划任务只在 Host 运行时投递；关闭插件前请先停掉或改回插件自建的任务，否则投递到的会话会调用不到工具。
- 日报只看文件与会话痕迹，线下工作仍需手动补一句。
